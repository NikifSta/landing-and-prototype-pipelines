# 05 — Описать сущности и навигацию

**Исполнитель:** UX-архитектор.

**Вход:** полный `product/APP_BRIEF.md`, `product/CONFIRMED_INTENT.md`; `product/FEATURE_MATRIX.md` — только для оснований; [CONTRACTS](../CONTRACTS.md).

**Действия**

Документ добавляет к `APP_BRIEF.md` только сущности с типами содержимого и навигацию. Продукт не пересказывай: правила, функции и задачи связывай ссылками на разделы и ID `APP_BRIEF.md`. Раскладку, модальные окна и состояния здесь не проектируй.

**Сущности.** Для каждой E-ID: термин и отличие от соседних понятий (один термин — одно понятие, синонимы обозначь), зачем она пользователю, принадлежность, прямой доступ или родительский контекст, ссылки на J, FEA и D-ID. Для каждого отображаемого свойства укажи тип содержимого — короткий текст, длинный текст, число, дата, список, вложение; это вход норм объёма этапа 12. Свойства, нужные для согласованного содержимого демо, включи; серверную схему не проектируй. Связи — «E → отношение → E» с множественностью и влиянием подтверждённых операций на связи.

**Дерево разделов и окон.** Вложенный Markdown-список: IA-ID, название, точка назначения или внутренняя область, роль, сущности и результаты, J и E-ID. Организуй по задачам, а не как меню таблиц данных; самостоятельный раздел нужен, когда пользователь обращается к нему самостоятельно. У каждого узла — строка «Понять или сравнить»: что пользователь должен здесь понять, найти или сопоставить. Условия, меняющие структуру узла (работа параллельно с другим делом, длинный список, редкое действие), укажи при узле с основанием из `APP_BRIEF.md`. Затем опиши начальную точку, постоянную и локальную навигацию, внешние входы с возвратом, альтернативные входы к сущностям и сквозные переходы «IA → основание → IA».

**Неполноты APP_BRIEF.** Сверь задание с моделью: задачи без места в дереве, сущности без свойств, нужных сценарию, противоречащие правила, пропущенные действия для завершения задачи. Каждую неполноту запиши с адресом раздела. Неясный вывод закрой минимальной помеченной гипотезой по CONTRACTS; неполноту или конфликт продукта верни в 04 одним пакетом.

**Выход и потребитель:** `product/ENTITIES_AND_NAVIGATION.md`: сущности с типами содержимого и связями; дерево разделов и окон со строками «Понять или сравнить»; навигация и сквозные переходы; неполноты `APP_BRIEF.md` → сценарии 09, состояния 10, ключевой экран 11, данные 12, раскладки 13, экраны 19.

**Готовность:** Все сущности выбранного объёма и их связи описаны, у каждого отображаемого свойства есть тип содержимого; все задачи и сущности находят место в дереве; у каждого узла есть строка «Понять или сравнить»; связанные области достижимы без необъяснимых разрывов; пересказа `APP_BRIEF.md` нет.

**Возврат:** Ошибка термина, связи или навигации — здесь; неполнота или конфликт продукта → 04 по лимиту возвратов CONTRACTS. Изменение узлов обновляет зависимые ID.
