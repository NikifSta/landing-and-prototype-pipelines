# 18 — Перенести выбранный дизайн в код: дизайн-система и ключевой экран

**Исполнитель:** автор кода, новая сессия; он же продолжает 19 и правки по сверке и со Стопа 5 на 20 ([правила запуска сессий](../contracts-orchestrator-session-launch-and-stage-chains.md), «Исполнители и сессии»).

**Вход:** выбор дизайна в «Выборах пользователя» `RUN.md`; выбранный `designs/design-0N/` (HTML, `assets/`, `DESIGN.md`, снимок); открытые замечания выбранного дизайна (правила проверок, «Проверки», пункт «После второго прохода») с подробностями в `designs/DESIGN_REVIEW.md`; `product/KEY_SCREEN_AND_DEMO_ROUTE.md`; `product/ENTITIES_AND_NAVIGATION.md`; `product/DEMO_STATES.json`; полный `product/DEMO_DATASET.json`; полный `product/APP_BRIEF.md`; [порог качества структуры экрана](../app-ui-layout-structure-quality-floor.md), [порог студийного качества](../app-ui-studio-quality-floor.md); [правила приоритета и структуры](../app-ui-content-priority-and-structure-rules.md); `designs/STYLE_BRIEF.md`; `references/CALIBRATION.md`; [CONTRACTS](../CONTRACTS.md), [правила демо](../contracts-demo-data-behavior-format-and-quality.md) и [правила проверок](../contracts-reviews-and-result-versions.md) целиком.

**Действия**

Сверь ID выбранного дизайна в `RUN.md` с папкой, по которой работаешь. Без явного выбора пользователя код не создаётся.

Выбери стек, который собирается в статические файлы в `app/dist/` и отдаётся одной командой локального статического сервера; backend не нужен. Маршрутизация — через адрес после `#`, чтобы сборка работала и из самодостаточного HTML-файла с диска.

Вынеси из ключевого экрана значения в токены — единственный источник значений в коде:

- пара шрифтов и шкала кеглей;
- шесть цветовых ролей;
- отступы с шагом 4 px;
- радиусы одной шкалы;
- тени — не больше трёх уровней;
- движение — длительности и кривые по разделу «Движение» порога.

Сделай компоненты, которые нужны главным страницам и вспомогательным экранам из `KEY_SCREEN_AND_DEMO_ROUTE.md`, только через токены: каркас окна, боковые панели, шапка, кнопки, строки списков, карточки, поля, метки. У каждого интерактивного компонента — обычное состояние, наведение, видимый фокус, нажатие, неактивное. Шрифты и прочие ресурсы — локально.

Служебные страницы внутри приложения; в обычном маршруте демо на них нет ссылок:

- `#/design-system` — страница-образец: каждый компонент во всех пяти состояниях;
- `#/frames/<FRAME-ID>` — просмотрщик кадров: экран в заданном состоянии с заданными записями, без переходов;
- `#/frames` — список кадров по порядку маршрута показа с переходом «назад / вперёд».

Собери ключевой экран в состоянии из `KEY_SCREEN_AND_DEMO_ROUTE.md` из компонентов и записей `DEMO_DATASET.json` по ID — это кадр `FRAME-00`. Просмотрщик показывает кадр целой страницей. Сними его инструментом снимков по адресу просмотрщика в `windows/frames/FRAME-00-key-screen/window.png`. Сравни снимок со снимком выбранного дизайна рядом и устрани расхождения в композиции, типографике и деталях, исправляя систему, а не экран. Закрой открытые замечания выбранного дизайна.

Инструмент снимков — [html_mockup_screenshot_capturer.py](../tools/html_mockup_screenshot_capturer.py) с `--url`, через `/home/ivan/.local/bin/run-bounded-check`, по разделу «Формат и размер» правил демо, с уменьшенным движением.

Запиши в `app/DESIGN_SYSTEM.md`: стек; команды установки, сборки, запуска и сброса данных; путь `app/dist/`; адреса служебных страниц; значения по ролям; список компонентов с назначением и состояниями; правило для этапа 19 — экраны собираются только из компонентов системы, недостающий компонент добавляется в систему и на страницу-образец.

**Выход и потребитель:** `app/` с токенами, компонентами, служебными страницами и ключевым экраном; `app/DESIGN_SYSTEM.md`; `windows/frames/FRAME-00-key-screen/window.png` → экраны 19, сверка и Стоп 5 на 20, связка 22–23.

**Готовность:** Ключевой экран в коде совпадает со снимком выбранного дизайна целой страницей по композиции, типографике и деталям; токены — единственный источник значений; у каждого интерактивного компонента на странице-образце показаны все пять состояний; сборка отдаётся одной командой.

**Возврат:** Проверяющего у этапа нет: снимки рядом сравнивает сам автор (см. «Действия»), ошибки системы, найденные сверкой оркестратора или пользователем на 20, возвращаются сюда. Существенная смена направления выбранного дизайна требует нового явного выбора пользователя на 17.
