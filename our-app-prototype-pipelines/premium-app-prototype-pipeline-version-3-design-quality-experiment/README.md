# Premium App Prototype Pipeline — версия 3, эксперимент с дизайнерским качеством

**Экспериментальная версия.** Попытка поднять дизайнерское качество экранов — вкус и уровень, а не аккуратность исполнения. Это копия [версии 2](../premium-app-prototype-pipeline-version-2/) с тремя изменениями на этапах дизайна:

- **планка уровня** — среди референсов этапа 15 есть эталоны планки: продукты, признанные именно за дизайн; дизайны тянутся к ним, а не к среднему рынку;
- **критика уровня** — проверяющий выбранного дизайна на этапе 17 сравнивает его с эталоном как арт-директор и даёт пять правок уровня;
- **замысел у каждого варианта** — задание дизайна на этапе 16 начинается с замысла; главный элемент подаётся типографикой и местом, смелость — одна фирменная деталь; приёмы эталона не переносятся; последний шаг автора — убрать лишнее рядом с эталоном; принятый прежде дизайн продукта — основа, которую варианты должны превзойти.

Версия 2 — рабочая и не меняется. Какая версия останется рабочей, решает Иван по итогам запусков.

Пайплайн создаёт экраны приложения в коде — frontend-прототип маршрута показа для лендинга. Финал — экраны, подтверждённые на Стопе 5; переходами в кликабельное демо они не связываются. Версия 1.14 с этапами демо заморожена в [../premium-app-prototype-pipeline/](../premium-app-prototype-pipeline/). Цель — очень удобный интерфейс студийного качества, заметно отличающийся от типового результата генерации. Студийное качество — уровень исполнения, а не стиль; стиль выбирает пользователь.

Путь: идея и исследование конкурентов (или перенос принятого исследования прежнего запуска) → продуктовая модель → ключевой экран и страницы демо → данные реального объёма → пять серых раскладок ключевого экрана → пять дизайнов ключевого экрана в выбранном стиле → дизайн-система и все экраны маршрута показа в коде: главные страницы (по умолчанию пять) и вспомогательные экраны.

## Пять остановок

1. **Идея.** Пользователь подтверждает идею, свои отличия от конкурентов, режим охвата (по заданию или с расширением функциями конкурентов) и географию исследования: западные или российские сервисы.
2. **Ключевой экран, страницы демо и стиль.** Пользователь подтверждает главные страницы маршрута показа (по умолчанию пять), ключевой экран, главный сценарий и вспомогательные экраны и выбирает стиль дизайна.
3. **Раскладка.** Пользователь выбирает одну из пяти раскладок ключевого экрана и подтверждает или меняет стиль.
4. **Дизайн.** Пользователь выбирает один из пяти дизайнов ключевого экрана.
5. **Экраны.** Пользователь подтверждает все экраны маршрута показа, сверстанные в коде на дизайн-системе выбранного дизайна; получает ссылку на страницу запуска. Подтверждение завершает запуск.

Между остановками работа идёт автономно, одной цепочкой служб; на каждом этапе с проверяющим — не больше двух проходов проверки.

- [app-ui-style-family-menu.md](app-ui-style-family-menu.md) — меню стилей для остановок 2 и 3.
- [prompts/](prompts/) — промпты этапов 00–20 (номера 03 и 06–08 не используются); у этапа 16 два файла — основной и правила заданий для автора заданий.
- [tools/html_mockup_screenshot_capturer.py](tools/html_mockup_screenshot_capturer.py) — снимок самостоятельного HTML-макета (`--html`) или экрана приложения по адресу (`--url`, например просмотрщик кадров `#/frames/<FRAME-ID>`) — вся страница шириной 1440 с коэффициентом 2 (для страницы выше предела изображения коэффициент снижается, страница не обрезается) и отчёт: высота страницы, коэффициент, скрытое переполнение, блоки с внутренней прокруткой; с `--window-at-scroll-y` снимает только окно — для пункта «Проверка деталей» [правил проверок](contracts-reviews-and-result-versions.md); запускается через `run-bounded-check`.
- [tools/demo_dataset_parts_merger.py](tools/demo_dataset_parts_merger.py) — склейка каркаса и параллельно сгенерированных частей данных этапа 12 в `DEMO_DATASET.json`; не пишет файл при конфликте полей, повторе ID или ссылке на несуществующую запись.
- [tools/static_build_single_html_exporter.py](tools/static_build_single_html_exporter.py) — упаковка статической сборки демо (`dist/`) в один самодостаточный HTML, который открывается с диска без сервера: скрипт, стили и шрифты встраиваются, файлы звука — data URI через подмену `src` у `<audio>`/`<video>`; `--start-route` открывает файл на заданном маршруте (для Стопа 5 — список кадров `#/frames`); сборка не меняется.
- [tools/prototype_run_page_publisher.py](tools/prototype_run_page_publisher.py) — выкладка материала показа запуска на страницу запуска `https://my.holdi.ai/prototypes/<продукт>-<код>/`, как у лендингов: оглавление со ссылками на живые HTML-страницы вариантов с прошлыми кругами и на файл экранов; галереи, снимки и рабочие файлы не выкладываются; сервер повторяет текущий состав показа; после выкладки проверяет, что страница открывается.
- [Дизайн пайплайна и ревью App Prototype Factory](../../docs/specs/realised/2026-09-24-premium-app-prototype-pipeline-design.md). Уточнения после независимой проверки перечислены в конце спецификации; при расхождении действуют файлы этой папки.
