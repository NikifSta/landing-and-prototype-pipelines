# Premium App Prototype Pipeline

**Заморожено 29.09.2026.** Версия 1.14 сохранена для истории и для новых запусков не используется; действующая — [версия 2](../premium-app-prototype-pipeline-version-2/PIPELINE.md): финал — экраны на Стопе 5, этапов демо нет. Инструменты `tools/` перенесены туда.

Пайплайн создаёт интерактивный frontend-прототип приложения для показа на лендинге. Цель — очень удобный интерфейс студийного качества, заметно отличающийся от типового результата генерации. Студийное качество — уровень исполнения, а не стиль; стиль выбирает пользователь.

Путь: идея и исследование конкурентов (или перенос принятого исследования прежнего запуска) → продуктовая модель → ключевой экран и страницы демо → данные реального объёма → пять серых раскладок ключевого экрана → пять дизайнов ключевого экрана в выбранном стиле → дизайн-система и все экраны маршрута показа сразу в коде демо → связка экранов в сценарии: frontend-демо главных страниц маршрута показа (по умолчанию пяти).

## Пять остановок

1. **Идея.** Пользователь подтверждает идею, свои отличия от конкурентов и режим охвата: по заданию или с расширением функциями конкурентов.
2. **Ключевой экран, страницы демо и стиль.** Пользователь подтверждает главные страницы маршрута показа (по умолчанию пять), ключевой экран, главный сценарий и вспомогательные экраны и выбирает стиль дизайна.
3. **Раскладка.** Пользователь выбирает одну из пяти раскладок ключевого экрана и подтверждает или меняет стиль.
4. **Дизайн.** Пользователь выбирает один из пяти дизайнов ключевого экрана.
5. **Экраны.** Пользователь подтверждает все экраны маршрута показа, сверстанные в коде на дизайн-системе выбранного дизайна; получает ссылку на страницу запуска. Только после этого экраны связываются в сценарии.

Между остановками работа идёт автономно, одной цепочкой служб; на каждом этапе с проверяющим — не больше двух проходов проверки, а проверка демо делает второй проход только при существенных дефектах первого.

- [prompts/](prompts/) — 21 промпт этапов (номера 03, 06–08 и 21 не используются).
- [tools/html_mockup_screenshot_capturer.py](tools/html_mockup_screenshot_capturer.py) — снимок самостоятельного HTML-макета (`--html`) или экрана приложения по адресу (`--url`, например просмотрщик кадров `#/frames/<FRAME-ID>`) — вся страница шириной 1440 с коэффициентом 2 (для страницы выше предела изображения коэффициент снижается, страница не обрезается) и отчёт: высота страницы, коэффициент, скрытое переполнение, блоки с внутренней прокруткой; с `--window-at-scroll-y` снимает только окно — для пункта «Проверка деталей» [правил проверок](contracts-reviews-and-result-versions.md); запускается через `run-bounded-check`.
- [tools/demo_dataset_parts_merger.py](tools/demo_dataset_parts_merger.py) — склейка каркаса и параллельно сгенерированных частей данных этапа 12 в `DEMO_DATASET.json`; не пишет файл при конфликте полей, повторе ID или ссылке на несуществующую запись.
- [tools/static_build_single_html_exporter.py](tools/static_build_single_html_exporter.py) — упаковка статической сборки демо (`dist/`) в один самодостаточный HTML, который открывается с диска без сервера: скрипт, стили и шрифты встраиваются, файлы звука — data URI через подмену `src` у `<audio>`/`<video>`; `--start-route` открывает файл на заданном маршруте (для Стопа 5 — список кадров `#/frames`); сборка не меняется.
- [tools/prototype_run_page_publisher.py](tools/prototype_run_page_publisher.py) — выкладка материала показа запуска на страницу запуска `https://my.holdi.ai/prototypes/<продукт>-<код>/`: галереи, страницы и снимки вариантов с прошлыми кругами, экраны, после этапа 25 — демо; рабочие файлы не выкладываются; сервер повторяет текущий состав показа; после выкладки проверяет, что страница открывается.
