# App Prototype Factory

Пять методов автоматически готовят дизайны в PDF. Пользователь выбирает один вариант, после чего создаётся одно интерактивное приложение. До выбора главный результат — внешний вид и структура окон; коротких правдоподобных примеров достаточно, детальная доводка выполняется только в выбранной ветке.

## Выбрать продуктовый охват

Режим охвата применяется и в SINGLE, и в ALL:

- **BRIEF_DRIVEN — по исходному заданию:** обычный синтез вокруг подтверждённых задач; действует по умолчанию.
- **COMPETITOR_EXPANSION — расширение по конкурентам:** исследовать функции и глубину трёх сервисов, выявить значимые пробелы исходного продукта и самостоятельно включить полезные дополнения в пределах его целей и ограничений. Сохранить исходные требования; объяснить исключения. Независимо проверить состав, провести принятые функции через APP_BRIEF, UX, данные, макеты и выбранное приложение.

> Выполни ALL в режиме COMPETITOR_EXPANSION — «Расширение продукта по конкурентам». Дополни исходную идею полезными базовыми возможностями и сильными находками трёх исследованных сервисов. Сохрани мои требования и ограничения. После общей галереи дождись выбора одного дизайна.

Выбор режима разрешает обоснованные дополнения без согласования каждой функции. Ровно три функциональных исследования и 10 визуальных референсов остаются отдельными этапами. Правила выбора, проверки и перехода существующего запуска — в [CONTRACTS](pipelines/pipeline-01/CONTRACTS.md). Изменение инструкций само по себе не пересоздаёт готовые результаты.

## Запустить все методы

> Выполни ALL по CONTRACTS и таблицам PIPELINE. Один раз подготовь задание, исследование трёх сервисов, UX-документы, данные, пять нейтральных UX-PDF этапа 12 и общий набор 10 визуальных референсов этапа 14. После PACKAGE_READY каждый из пяти методов автоматически выбирает UX-основу и создаёт пять design.pdf. До ручного выбора код приложения не писать. Собери общую галерею 25 дизайнов и остановись в AWAITING_DESIGN_SELECTION. После явного выбора пользователя продолжай только выбранную ветку и выдай одно приложение; остальные макеты сохрани.

APP_BRIEF — единый источник продуктовых фактов; следующие документы добавляют свои модели и решения. Функциональное исследование, поиск 10 визуальных референсов и данные не размножаются. В 16 методы выбирают примеры из общей десятки. Для desktop-web макеты, приложение и проверки используют только 1920×1080 CSS px, масштаб браузера 100%, масштаб снимка 1; адаптация к другим размерам не выполняется. Для другой явно выбранной платформы фиксируется один подходящий размер. Методы работают в отдельных папках и контекстах, волнами при лимите слотов. Общий оркестратор владеет подготовкой и G/DESIGN_SELECTION.json; G — папка общего запуска вне замороженного пакета. Неизмеренные затраты отмечаются как неизвестные.

## Запустить один метод

> Выполни PIPELINE в режиме SINGLE. После общей подготовки автоматически создай пять design.pdf выбранного метода. Предъяви их пользователю и дождись одного выбора. Затем создай и проверь одно приложение по выбранному дизайну.

Подтверждённые входы текущего запуска используются повторно. Пользовательский выбор дизайна не сбрасывает run-id и бюджеты: два раунда общей подготовки и два общих раунда на метод, включая его макеты и код при выборе.

## Методы

| Метод | Подготовка до выбора | Реализация после выбора, если выбран этот метод |
|---|---|---|
| [01 — Архитектура](pipelines/pipeline-01/PIPELINE.md) | Карта экранов, связей и маршрутов | Структура → связанные области → полный интерфейс |
| [02 — Визуальный эталон](pipelines/pipeline-02/PIPELINE.md) | Композиции и разбор задач по страницам | Семейства экранов с проверкой задач |
| [03 — Законченный сценарий](pipelines/pipeline-03/PIPELINE.md) | Макеты представительного пути | Один работающий маршрут → остальные |
| [04 — Компоненты](pipelines/pipeline-04/PIPELINE.md) | Повторяемые визуальные части окон | Проверка основы → компоненты → экраны |
| [05 — Независимые варианты](pipelines/pipeline-05/PIPELINE.md) | Пять независимых авторских дизайнов | Реализация одного выбранного направления |

Полные правила — CONTRACTS каждой папки; различия — PIPELINE_COMPARISON. source-pipeline и прежние ZIP сохраняют историю. Готовность инструкций, готовность PDF и готовность приложения — отдельные результаты.
