# 11 — Подготовить реалистичные данные

**Исполнитель:** генератор синтетических данных

**Вход:** весь PRODUCT/UX/Domain/IA/flows пакет и STATE_MATRIX.

**Действия**

Создай один канонический вымышленный набор со стабильными ID, связями и хронологией. Сначала определи минимум обычных записей для однократного покрытия всех flows/states, затем доведи до примерно тройного объёма с типичной вариативностью. Фиксированные единичные сущности, например владелец пространства, не размножай искусственно; правило относится к рабочим коллекциям. Подробность объекта соответствует его смыслу: длинная встреча имеет согласованные участников, темы, расшифровку, результаты и задачи, если они входят в модель.

Объём вложенных данных соответствует реальному масштабу объекта, а не минимуму для показа. Для каждой коллекции, размер которой зависит от свойства родителя — длительности, числа участников, размера документа, периода, — выведи из реальной практики норму пересчёта и выдержи её в каждой записи. Пример: расшифровка встречи — около 90–130 слов на минуту записи и новая реплика в среднем каждые 15–40 секунд, по всей длительности без пропусков, кроме отмеченных пауз; полуторачасовая встреча — примерно 8–12 тыс. слов и 130–360 реплик, а не несколько строк. Темы, итоги и задачи растут с длительностью и числом участников и опираются на фрагменты из всей записи. Если полный объём невыполним, не сокращай молча — зафиксируй ограничение в issues.

SYNTHETIC_DATASET.json — валидный JSON: status, sources, context с language/locale/timezone/reference_time, объёмом по коллекциям и нормами объёма вложенных данных с основанием и фактическим диапазоном; records по E-ID; scenario_fixtures; state_fixtures; issues при наличии. Запись: id, предусмотренные моделью поля, ссылки на записи по ID. Scenario fixture: id, flow_refs, record_refs, state_fixture_refs. State fixture: id, ui_area_ref, state_ref, record_refs и/или context для запроса, фильтра, временного статуса. Канонические записи не дублируй внутри fixtures.

Каждому flow назначь достаточные записи, каждому состоянию — fixture, выполняющий condition. Тексты предметные, подробные и на языке продукта. Служебные подписи, lorem ipsum, настоящие личные данные и искусственный stress-набор не нужны. Следующие этапы получают точные байты этого файла.

**Выход и потребитель:** SYNTHETIC_DATASET.json → пять UX-концепций, все методы и проверки.

**Готовность:** Все ссылки/условия/хронология согласованы; flows/states покрыты fixtures; объём каждой вложенной коллекции укладывается в свою норму, ни одна запись не выглядит обрезанной выборкой; содержимого хватает для реалистичного сравнения на одном наборе.

**Возврат:** Ошибка записи → здесь; нехватка отображаемого свойства → 07 с согласованным обновлением зависимостей; условие fixture → 10. Новый продуктовый объём не создавай.
