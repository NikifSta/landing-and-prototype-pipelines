# 17 — Проверить архитектуру по экранам

**Исполнитель:** UX-архитектор.

**Вход:** MODEL, выбранный UX-PDF, REFERENCES, P и R/inputs.

**Действия**

Проследи ключевые маршруты по экранам и карте связей: где вход, действие, следующий экран, результат и возврат. Проверь роли основных областей и связь выбранного объекта с его содержимым. Подробную карту всех маршрутов и распространения изменений отложи до реализации выбранной ветки. Наблюдения на макете отделяй от гипотез о поведении.

Уточни экранную структуру и MODEL для пяти дизайнов 18. Нейтральный frontend-каркас до выбора пользователя не создаётся. Если этот метод будет выбран в 19, сначала реализуй структуру и связи в 20, затем расширь приложение по карте областей в 21.

**Выход и потребитель:** MODEL, уточнения экранов и краткие наблюдения → дизайнеры 18, реализация выбранного варианта 20/21.

**Готовность:** Понятны маршрут, объекты и доступ к действиям; полный функциональный объём сохранён во входах для последующей реализации.

**Возврат:** Модель/навигация → 15; экранная структура → здесь; визуальные решения → 18. Общий бюджет R сохраняется.
