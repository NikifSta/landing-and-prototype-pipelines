# pipeline-05 — Через независимые варианты и отбор

Версия 1.1, 22 сентября 2026. Полный процесс от идеи до интерактивного frontend-демо для лендинга. Инструкции готовы к запуску агентом; продуктовый прогон не выполнен. Требования и схемы: [CONTRACTS.md](CONTRACTS.md).

**Единица решения:** Конкурирующая гипотеза с рабочим образцом. **Гипотеза преимущества:** Независимые авторы увеличивают разнообразие решений; слепая проверка снижает влияние авторского объяснения. **Риск:** Эффектная подача и затраты на кандидатов могут перевесить пользу; охват и условия проверки одинаковы. Преимущество метода ещё не подтверждено сравнительными прогонами.

## Команда одиночного запуска

> Прочитай PIPELINE.md и CONTRACTS.md целиком. Создай новый runs/<UTC-дата-время>-<продукт>/ со статусом IN_PROGRESS, режимом SINGLE и preparation/. Выполни перечисленные промпты в указанном порядке. Начни с темы приложения, получи подтверждение понимания и пакета отличий, затем автономно подготовь варианты дизайна в PDF и остановись на этапе 19 для выбора пользователя. Код создавай только после USER_SELECTED и только для выбранной ветки. Сохраняй подтверждённые этапы и общий счётчик исправлений.

До ответа пользователя этап 00 ведёт предметный разговор. После подтверждения работают правила автономности. Рабочая почта — только для разрешённого доступа при исследовании. Возможности инструментария проверяются до обещания результата.

## Запуск в общей пятёрке

Внешний оркестратор выполняет идентичные этапы 00–14 один раз, замораживает пакет и передаёт его полную копию в R/preparation вместе с inputs. Проверь PACKAGE_READY и хеши; далее начни с первого этапа метода в таблице после 14. Общий пакет содержит 10 визуальных референсов этапа 14; на этапе 16 выбирай примеры из них. Своё исследование, повторный визуальный поиск и повторный UX-пул не создавай. При возобновлении прочитай EXECUTION_POLICY из inputs, если она есть. После отделения методы пишут только в свои R. Если папка запуска переносится, она включает preparation, inputs, код и локальные доказательства.

До ручного выбора приоритет — внешний вид и структура окон по разделу «Точность макетов до выбора дизайна» в CONTRACTS. Детальное наполнение, полный набор состояний и точные параметры доводит только выбранная ветка.

## Порядок исполнения

Номера файлов — идентификаторы этапов; выполняй по строкам таблицы, а не по алфавиту. 02 выполняется отдельным исследователем для каждого сервиса; 03 — общий gate исследования. Этап 13 опционален. Остальные этапы обязательны. Каждый промпт содержит исполнителя, вход, действия, выход/потребителя, готовность и возврат. В ALL все методы доходят до общей галереи 19; после пользовательского выбора продолжается только одна ветка. До выбора любые этапы выполняются без кода приложения.

В ALL общая галерея содержит 25 вариантов; пользователь выбирает один дизайн (USER_SELECTED). Только выбранный метод продолжает этапы после 19 и создаёт одно приложение. Остальные сохраняют макеты со статусом NOT_SELECTED.

## Карта возвратов

Источник → 16; различимость заданий/равный охват → 15; реализация кандидата → 18; процедура отбора → 19; модель победителя → 17; система → 20; полный продукт → 21. После исправления повтори затронутые проверки, а финальную приёмку привяжи к точной версии. Общий пакет не изменяй локально: производные решения сохраняются в working-ux по CONTRACTS.

## Среда и роли

Нужны доступ к актуальному интернету, поддерживаемая авторизация, исследовательские субагенты требуемого уровня, независимый reviewer, локальная среда frontend и браузерная визуальная проверка. Записывай фактически доступную конфигурацию. При недоступном обязательном средстве сохраняй BLOCKED и выполненное; имитация исследования или самооценка не заменяют его.

## Передача результата

До выбора выдай дизайн-PDF с результатами проверки в общую галерею. После USER_SELECTED только выбранная ветка выдаёт prototype с исходниками/ассетами/lockfile, HANDOFF, MODEL/DESIGN, COVERAGE, реальные кадры, галерею всех PDF и один архив приложения с честным статусом. Неизмеренные затраты и непроверенные свойства обозначай явно. Публикация определяется поручением.

Для возобновления: «Прочитай PIPELINE и RUN указанного запуска. Проверь входные хеши и checkpoint, продолжи с указанного следующего этапа, сохранив счётчики и уже выполненные проверки». Новое существенное требование пользователя создаёт явную новую версию задания.
