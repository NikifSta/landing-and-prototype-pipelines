# 21 — Собрать весь согласованный интерфейс

**Исполнитель:** дизайнер и frontend-исполнитель

**Вход:** MODEL, DESIGN, prototype, P и R/inputs, REFERENCES, CONTRACTS; правила расширения метода.

**Действия**

Выполняй только для ветки USER_SELECTED из G/DESIGN_SELECTION.json. Проверь method-ID и выбранную версию дизайна; без явного выбора пользователя код и функциональные проверки не начинай.

Развивай единственное приложение по выбранному пользователем дизайну. Метод 01 расширяет по карте областей/связей, 02 — по композиционным семействам с проверкой задач, 03 — законченными маршрутами, 04 — из общей компонентной системы, 05 — из модели победителя. Полные действия метода заданы в PIPELINE и промптах 15/17.

Покрой все flows, вспомогательные действия, states и D-ID. Навигация ведёт к содержимому; операции используют введённые значения и обновляют связанные представления. Поиск/фильтры зависят от запроса; AI и внешние действия дают согласованный подготовленный результат с видимыми переходами. Reset детерминированно восстанавливает DATA. Состояния можно показать через fixtures вне продуктового UI.

В COMPETITOR_EXPANSION реализуй каждую принятую новую/усиленную функцию до результата на глубине APP_BRIEF; используй общие сущности и связанные данные. Заполни competitive_features в COVERAGE по CONTRACTS. Исходные сценарии и D-ID сохраняются; набор окон PDF не ограничивает функциональный объём приложения.

Применяй общие токены/компоненты, тексты, компоновку в единственном размере и движение ко всем экранам. Перед первой проверкой каждого нового участка заверши его наблюдаемый результат. Ошибки уже предъявленных участков исправляй только в общих раундах. Сверь пересечения маршрутов и обновление связанных данных. Обнови MODEL/рабочие UX-копии и COVERAGE по фактическому коду; источники P не меняй.

**Выход и потребитель:** Полный R/prototype/, MODEL, DESIGN и COVERAGE.json → проверка/приёмка; commands в HANDOFF.

**Готовность:** У каждого сценария есть завершённый путь, у каждого состояния — воспроизводимый вход; неподкреплённых уведомлений об успехе нет.

**Возврат:** Причину исправляй по карте метода: модель/связи → 15/17; система → 20; локальная реализация → здесь. Порог и объём не сокращай ради лимита.
