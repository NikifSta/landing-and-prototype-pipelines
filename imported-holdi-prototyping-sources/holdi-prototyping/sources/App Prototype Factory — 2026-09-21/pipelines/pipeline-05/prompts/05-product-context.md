# 05 — Сформировать Product Context

**Исполнитель:** продуктовый аналитик

**Вход:** CONFIRMED_INTENT, полный APP_BRIEF, FEATURE_MATRIX.

**Действия**

Преобразуй задачи APP_BRIEF в карту J-ID: «когда → хочу → чтобы», обычная последовательность работы (workflow), ссылки на соответствующие разделы APP_BRIEF и FEA/D-ID. Свяжи с задачами все функции, отличия, вспомогательные действия и видимую автоматизацию; общие правила и условия связывай с применимыми J-ID.

Для групп пользователей, объёма показа, внешних условий, понятий/связей и автоматизации укажи адреса полного описания в APP_BRIEF. PRODUCT_CONTEXT добавляет структуру задач и связи, не пересказывает продукт. Существенную гипотезу связывай с источником, зависимыми J-ID и следствием ошибки; новую продуктовую неопределённость возвращай в 04.

Лендинг остаётся дополнительным материалом. Админка, аккаунт и биллинг требуют основания в APP_BRIEF; если необходимое для завершения сценария действие там пропущено, верни неполноту в 04. Решения о layout здесь не принимай.

**Выход и потребитель:** PRODUCT_CONTEXT.md: FINAL, ссылка на полный APP_BRIEF, карта J-ID/workflow и D/FEA/J-связей → UX Context и остальные этапы вместе с APP_BRIEF.

**Готовность:** Все задачи, функции и отличия APP_BRIEF связаны с J-ID без потери правил; ссылки разрешаются. APP_BRIEF и карта достаточны для проектирования без повторного интервью.

**Возврат:** Пропуск связи или workflow → этот этап; неполнота либо конфликт продуктового задания → 04 по правилам источников. Передача готового контекста не требует нового подтверждения.
