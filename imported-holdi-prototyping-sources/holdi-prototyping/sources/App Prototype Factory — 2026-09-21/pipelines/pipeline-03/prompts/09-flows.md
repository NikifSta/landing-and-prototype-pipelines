# 09 — Описать все сценарии

**Исполнитель:** UX-дизайнер

**Вход:** PRODUCT_CONTEXT, UX_CONTEXT, DOMAIN_MODEL, INFORMATION_ARCHITECTURE, APP_BRIEF.

**Действия**

Покрой все самостоятельные сценарии в APP_BRIEF: основные, вспомогательные, повторные, обратные, настройки и видимую автоматизацию. Разделяй flows по самостоятельным триггеру/результату; маленькое действие внутри общей цели не выноси отдельно. Сохраняй правила сущностей и IA-ID.

Для F-ID укажи J/UXR/FEA/D/E/IA-связи, цель/результат, предусловие/триггер. Основной маршрут — таблица «шаг | участник | действие/событие | наблюдаемый результат/состояние». Разделяй пользователя, систему и подтверждённую внешнюю сторону; скрытую обработку сворачивай в видимый шаг. Добавь только развилки, меняющие результат, завершение и следующие flow ID.

Карта Mermaid полезна при передаче управления между flows; внутренние шаги не дублируй. Состояния для следующего этапа укажи как F/IA → состояние → событие → состояние. Подробную матрицу, layout и технические алгоритмы оставь следующим этапам.

**Выход и потребитель:** USER_FLOWS.md: FINAL, карта при необходимости, полные маршруты, значимые развилки, состояния и гипотезы → states, данные, концепции, приёмка.

**Готовность:** Каждая задача/функция/D-ID имеет путь к результату; все подтверждённые самостоятельные сценарии учтены, переходы согласованы с IA.

**Возврат:** Недостижимый путь → 08 с обновлением зависимостей; неверный порядок/развилка → здесь. Уточняющих продуктовых интервью нет.
