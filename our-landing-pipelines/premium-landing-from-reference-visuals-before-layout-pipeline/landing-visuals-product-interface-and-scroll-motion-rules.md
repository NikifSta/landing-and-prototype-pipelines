# Правила визуалов и движения

Читаются вместе с «Правилами для всех этапов» (`landing-pipeline-rules-for-all-stages.md`) и промптом каждого этапа.

## Интерфейс продукта

Если во входах есть готовый дизайн приложения, интерфейсы продукта на лендинге собираются из него: те же экраны, компоненты, типографика и данные в формате общего продуктового примера. Если его нет, интерфейс проектируется по фактам из входов.

- В итоговом состоянии визуала интерфейс — полный экран, без обрезки. По пути экран может собираться из элементов; приблизить деталь можно только после того, как экран показан целиком.
- То, о чём говорит секция, показывается движением элементов экрана или сменой экранов из прототипа приложения, если они в нём есть: пункт появляется, статус меняется, экран сменяется следующим по маршруту. Статичный снимок там, где секция говорит о действии, — брак.
- Телефон: если у приложения есть мобильные экраны — показываются они. Если нет — десктопный экран: сначала целиком, затем камера проходит по его частям в читаемом масштабе. Мобильные экраны, которых нет во входах, не рисуются.

## Стиль из приложения

Если во входах есть дизайн приложения, лендинг перекликается с ним: берёт его шрифты, палитру, скругления, тени и характер. Своё у лендинга — крупный масштаб, язык фото и видео, движение. Айдентика бренда из входов главнее дизайна приложения. Нет ни айдентики, ни дизайна приложения — стиль выбирает арт-дирекшн плана этапа 1.

## Типы визуала

Интерфейс продукта; продуктовая сцена (интерфейс в контексте использования); фотография (люди, места, предметы, продукт); иллюстрация; предметная или 3D-сцена; графическая или типографическая композиция; схема или график; видео под прокруткой (ролик, время которого идёт вместе с прокруткой); без визуала. Смешанный тип — только если без комбинации смысл не передаётся.

## Слои

Каждый визуал собирается из слоёв, которые при прокрутке движутся независимо:
- фотография, иллюстрация, предметная или 3D-сцена — чистый фон без движущихся объектов и каждый движущийся объект отдельным файлом с прозрачностью; передний план и дымка — тоже отдельными объектами; слои делает пайплайн изображений `dev/pipelines/landing-image-generator/`;
- интерфейс, продуктовая сцена, схема, график — окна, строки, подписи и фигуры отдельными HTML/SVG-элементами;
- видео под прокруткой — ролик и обложку из его первого кадра делает пайплайн видео `dev/pipelines/landing-video-generator/`; текст — HTML поверх ролика.

Цельная картинка без слоёв допустима только у иконок.

## Фото и видео

Для каждого визуала с фотографией или видео:
- Кадр — момент общего продуктового примера: кто из примера, где, что делает и на каком шаге сценария — до, во время или после работы продукта. Предмет, который ничего не делает в примере, в кадр не попадает.
- Если у продукта есть интерфейс, рядом с кадром — полный экран продукта в тот же момент: то же время, те же люди и данные. Экран — отдельный резкий HTML-слой поверх кадра или рядом с ним; интерфейс продукта внутри кадра не изображается.
- От референса берётся способ показа, а не предметы его изображений. Приём «продукт поверх того, что он заменяет» — только если по фактам из входов аудитория действительно этим пользуется.
- Кадр читается сам: он не превращается в размытую подложку под экраном.
- Свет и цвет кадра перекликаются с палитрой из раздела «Стиль из приложения».
- Visual Intent визуала содержит одну фразу: кто, где, что происходит и при чём тут продукт. Если такую фразу не составить — визуал меняется.

## Движение при прокрутке

- Механизм — движок scroll-craft: `.claude/skills/scroll-craft/engine/scrollcraft.js` и `scrollcraft.css` копируются в папку этапа без правок; своё поведение пиши в коде страницы на переменной `--sc-p` и своих атрибутах `data-sc-*`.
- Приём секции — приём её секции в разборе референса, названный и сделанный по каталогу `.claude/skills/scroll-craft/references/devices.md`. Движок его не повторяет — ближайший из каталога с записью в `stage-notes.md`; у секции референса нет движения — приём из каталога по чувству секции.
- Визуалы со слоями двигай по `.claude/skills/scroll-craft/references/hero-depth.md`: слои с разной скоростью, общие точки опоры, без дыр, двойников и ореолов.
- Кульминация получает самый длинный отрезок прокрутки, перед ней — более тихая секция.
- Изменение успевают заметить: каждый переход между состояниями, включая кульминацию, растянут минимум на два экрана прокрутки, и меняется крупное — главный объект секции или заметная часть экрана, а не мелкая деталь. На листе кадров съёмщика каждое состояние видно минимум на двух соседних кадрах.
- Если на листе кадров соседние состояния выглядят почти одинаково, изменение слишком слабое: усиль его — размытием, масштабом, сдвигом или сменой объекта.
- На странице не больше двух роликов под прокруткой: видео — самый тяжёлый элемент, третий ролик уже не удивляет.
- Текст — HTML поверх визуалов, никогда не внутри картинки или ролика. Звука нет.
- Двигай `transform` и `opacity`, шторки — `clip-path`.
- При выключенной анимации (`prefers-reduced-motion`) страница статична и полна: все тексты и визуалы видны, лишней прокрутки нет.
- Телефон — своё движение: свой кадр и ролик 9:16; минимальные отрезки те же, что на десктопе.
