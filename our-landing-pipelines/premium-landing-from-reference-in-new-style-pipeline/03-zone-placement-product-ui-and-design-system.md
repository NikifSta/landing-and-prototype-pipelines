# 4. Размещение остальных визуальных зон

Визуалы остальных зон создаёт этап 4. Для каждой такой зоны задай точное место и заполни поле Placement в её аннотации:
- тип визуала и важность: вспомогательный или без визуала;
- размеры и соотношение сторон на десктопе;
- фокус, безопасная область для текста, допустимое перекрытие;
- допустимое кадрирование; у интерфейса — по «Правилам визуалов и движения», раздел «Интерфейс продукта»;
- положение: во всю ширину, в контейнере или слоем;
- слои: какие части движутся отдельно и в каком порядке лежат;
- поведение на телефоне;
- редактируемый (HTML/SVG), растровый или видео;
- какие данные общего продуктового примера нужны.

Не заполняй зону псевдомокапом, потому что пустой контейнер выглядит незавершённым: точная пустая зона с ясной аннотацией лучше ложного «почти готового» визуала. Черновой визуал этапа 2 можно оставить как ориентир, пометив в аннотации, что это не финал.

# 5. Product UI: проектируй систему, не декоративную картинку

Если есть готовый дизайн приложения, Product UI берётся из него по «Правилам визуалов и движения», раздел «Интерфейс продукта»; ниже решается только то, чего в нём нет.

Product UI является исключением: его структурную систему нужно определить уже в Hi-Fi, потому что он влияет на layout и storytelling.

Определи:

- component language;
- typography;
- grid;
- spacing;
- controls;
- information hierarchy;
- states;
- iconography;
- data language;
- relationship с общей страницей.

Создавай структурные Product UI states в HTML/CSS/SVG; окна, строки и подписи — отдельными элементами, чтобы двигаться при прокрутке.

Но различай:

**Product UI architecture** — задача Hi-Fi;

**продуктовые сцены остальных зон** — задача этапа 4; данные — общий продуктовый пример.

Не создавай новый вымышленный dashboard для каждой секции.

# 6. Design System

Сформируй последовательную систему всего лендинга.

## Typography

Определи:

- display;
- H1 / H2 / H3;
- body;
- captions;
- labels;
- annotations;
- button typography;
- line-height;
- tracking;
- max line lengths;
- responsive behavior.

## Layout

Определи:

- grid десктопа и телефона;
- content width;
- gutters;
- column behavior;
- section spacing;
- vertical rhythm;
- alignment rules;
- full-bleed behavior;
- overlap rules.

## Core UI

Определи:

- navigation;
- buttons;
- controls;
- forms;
- pricing;
- cards / containers, только если они действительно нужны;
- product surfaces.

## Visual Language

Определи:

- palette;
- accent usage;
- borders;
- radii;
- shadows;
- blur;
- gradients;
- depth;
- texture principles;
- imagery treatment direction;
- illustration treatment direction;
- iconography;
- signature element behavior.

Количество визуальных приёмов должно быть ограниченным.

Качество должно возникать из **точности, последовательности, отбора и restraint**, а не количества эффектов.

---

# 7. Signature Element

Signature element выбранного арт-дирекшена должен стать системным принципом.

Развивай его по странице:

- иногда как главный композиционный объект;
- иногда как spatial principle;
- иногда как background behavior;
- иногда как небольшая деталь;
- иногда как движение при прокрутке.

Он должен повышать узнаваемость, но не превращаться в gimmick.

---

# 8. Craft и визуальное качество

Особенно внимательно проработай то, что действительно принадлежит Hi-Fi:

- размеры и интервалы;
- line-height;
- длину строк;
- optical alignment;
- масштаб заголовков;
- whitespace;
- баланс copy и visual zone;
- grid precision;
- surface hierarchy;
- borders / radii;
- shadow system;
- color relationships;
- masks / clipping logic;
- переходы между секциями;
- overall rhythm.

Не пытайся компенсировать отсутствие production asset декоративной детализацией контейнера вокруг него.

Избегай ощущения autogenerated SaaS template.

Premium quality чаще возникает из **точного решения того, что оставить, а не того, что ещё добавить**.

# 10. Десктоп и телефон

Реши обе версии на этом этапе. Десктоп — главный макет; телефон — отдельная композиция, а не уменьшенный десктоп: порядок, масштаб заголовков, кадрирование зон, слои и плотность решаются заново для узкого экрана. Проверь реальную отрисовку на 1440 и 390 px. Интерфейс на телефоне — по «Правилам визуалов и движения», раздел «Интерфейс продукта».
