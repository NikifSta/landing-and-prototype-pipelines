# Premium Landing From Reference In New Style Pipeline — лендинг по референсу в новом стиле

Четыре этапа от понравившегося сайта и нашего текста до страницы с движением при прокрутке, слоистыми визуалами и роликами на десктопе и телефоне. Сюжет страницы — как у референса: порядок и роль секций, способ донести мысль, показ продукта, приёмы прокрутки, фишка и кульминация. Вид — новый, один из трёх на выбор. Работает для любого продукта.

Основан на [пайплайне лендинга версии 5](../premium-landing-prototype-pipeline-version-5/README.md).

## Когда запускать

Только когда Иван прямо просит запустить пайплайн с копированием референса. Любой другой лендинг — в том числе по понравившемуся сайту или с референсами во входах — делает [пайплайн версии 5](../premium-landing-prototype-pipeline-version-5/README.md). Если неясно, о каком пайплайне просьба, — спроси Ивана, а не запускай этот.

## Входы запуска

- референс — ссылка на сайт, который нравится; если скрипт съёмки его не открыл — скриншоты или запись экрана;
- текст лендинга, разделённый на смысловые блоки;
- продукт, аудитория и подтверждённые факты о продукте;
- айдентика и ограничения бренда — либо «нет»;
- готовый дизайн приложения — либо «нет»;
- другие материалы продукта: фото, видео, логотип — либо «нет».

## Этапы

Каждый этап получает свой промпт, [правила для всех этапов](landing-pipeline-rules-for-all-stages.md), [правила визуалов и движения](landing-visuals-product-interface-and-scroll-motion-rules.md), входы запуска и результаты предыдущих этапов. Проверяющих нет: автор проходит самопроверку своего промпта и исправляет найденное.

1. [01-break-down-reference-and-lay-text-on-its-plot.md](01-break-down-reference-and-lay-text-on-its-plot.md) — разбор референса по секциям и прототип нашего текста по его сюжету в нейтральном оформлении: секции, задания на визуалы, общий продуктовый пример, чувства по секциям и кульминация.
2. [02-explore-three-art-directions-with-signature-moves.md](02-explore-three-art-directions-with-signature-moves.md) — три новых стиля на одних и тех же ключевых разделах; у всех сюжет и фишка референса, вид каждого заметно отличается от референса и от двух других.
   **Остановка: человек выбирает одно направление** по трём направлениям на странице запуска. Это единственное решение человека внутри процесса.
3. [03-build-page-around-anchor-visuals-with-scroll-motion.md](03-build-page-around-anchor-visuals-with-scroll-motion.md) — три опорных визуала слоями, затем вокруг них вся страница: десктоп и телефон, приёмы прокрутки референса, фишка целиком.
4. [04-produce-remaining-visuals-and-verify-scroll.md](04-produce-remaining-visuals-and-verify-scroll.md) — остальные визуалы слоями, встраивание в движение, проверки на пяти ширинах экрана и прокруткой.

Визуалы этапы заказывают двум пайплайнам: [landing-image-generator](../landing-image-generator/README.md) — изображения слоями, [landing-video-generator](../landing-video-generator/README.md) — ролики под прокрутку.

## Папка запуска

`dev/pipeline-workspace/<ГГГГ-ММ-ДД>-<продукт>-reference-landing/` (вне Git): `inputs/`, `stage-1/` … `stage-4/` и `stage-notes.md` — заметки всех этапов, по разделу на этап. Этапы 2–4 копируют в свою папку движок scroll-craft.

Кадры референса — `stage-1/lab/reference/`. Папка визуалов — `visuals/` в папке этапа: опорные визуалы этапа 3 — в `stage-3/visuals/`; этап 4 копирует страницу и визуалы этапа 3 в `stage-4/` и добавляет остальные в `stage-4/visuals/`.

## Съёмка референса

Скрипт открывает референс в Chrome на 1440 и 390 px, прокручивает колесом мыши по полэкрана, снимает кадр после каждого шага и сохраняет видимый текст страницы. Из корня проекта:

```bash
.venv/bin/python dev/pipelines/premium-landing-from-reference-in-new-style-pipeline/tools/reference_site_scroll_frame_capturer.py \
  --url <ссылка на референс> --output-folder <папка запуска>/stage-1/lab/reference
```

Результат: `desktop/frame-NNN.png`, `phone/frame-NNN.png`, `reference-page-text.txt`. На проход — не больше 150 кадров; при упоре скрипт предупреждает, что страница снята не целиком. Если сайт не открылся — скрипт называет причину; тогда нужны скриншоты или запись экрана референса. Кадры лежат в `lab/` и на страницу запуска не выкладываются.

## Показ на странице запуска

После каждого этапа тот, кто ведёт запуск, выкладывает готовые этапы на страницу запуска и отправляет Ивану в подтверждённый личный Telegram одно сообщение: ссылку на страницу запуска и прямую ссылку этапа. Инструмент — из пайплайна версии 5, названия этапов у него общие. Из корня проекта:

```bash
.venv/bin/python dev/pipelines/premium-landing-prototype-pipeline-version-5/tools/landing_run_page_publisher.py \
  --run-folder <папка запуска> --product-name "<название продукта>" --stage <номер этапа>
```

Выкладываются этапы с 1-го по указанный: папки `stage-N/` без `lab/`, `node_modules/`, заметок `*.md` и скрытых файлов, с оглавлением по этапам; ссылки оглавления открывают страницы в чистом просмотре без аннотаций. Страница запуска — одна постоянная ссылка `https://my.holdi.ai/prototypes/<продукт>-reference-landing-<код>/`, открывается без входа; адрес хранится в `published-run-page-address.txt` папки запуска. Если Telegram в сессии недоступен — ссылка даётся в ответе сессии с пометкой, что в Telegram она не ушла. Если выкладка не удалась — причина сообщается Ивану; файлы или показ в чате её не заменяют.

## Проверка прокруткой

Съёмщик скилла scroll-craft проходит страницу по точкам прокрутки, снимает кадры и лист кадров `sheet.png`, пишет `report.json` с мёртвой прокруткой, недопроявленными подсказками и контрастом. Один раз в папке запуска: `npm i playwright-core`. Затем из папки запуска:

```bash
SC=/home/ivan/claude-sandbox/hypothesis-tester/.claude/skills/scroll-craft
node "$SC/scripts/serve.mjs" --root <папка этапа> --port 4500 &
node "$SC/scripts/shoot.mjs" --url http://localhost:4500/<страница>.html --out <папка этапа>/lab/desktop
node "$SC/scripts/shoot.mjs" --url http://localhost:4500/<страница>.html --out <папка этапа>/lab/phone --width 390 --height 844
node "$SC/scripts/shoot.mjs" --url http://localhost:4500/<страница>.html --out <папка этапа>/lab/reduced --reduced-motion
```

Прочитай `sheet.png` каждого прогона: съёмщик доказывает, что кадры меняются, но не что композиция хороша. Реальный телефон он не проверяет.
