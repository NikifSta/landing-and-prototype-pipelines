# Этап 2. Одно из трёх арт-направлений с фишкой на ключевых разделах

Читай вместе с «Правилами для всех этапов» (`landing-pipeline-rules-for-all-stages.md`).

У нас уже есть готовый прототип лендинга продукта: определены структура, порядок разделов, тексты, основные смыслы, задания на визуалы, чувства по секциям и кульминация.

Следующий этап — не переделывать UX, структуру или контент, а найти сильный и узнаваемый **визуальный язык продукта**.

Этап делают три автора одновременно, каждый — одно направление. Ты — автор направления, номер которого дал ведущий. Результатов других авторов ты не видишь.

## Исходные материалы

Перед началом изучи:

- описание продукта;
- целевую аудиторию;
- позиционирование;
- ключевые преимущества;
- прототип этапа 1 и раздел «Этап 1» в `stage-notes.md`: общий продуктовый пример, чувства по секциям, кульминация;
- тексты прототипа;
- visual intent блоков;
- готовый дизайн приложения и реальные материалы продукта, если они есть;
- существующие брендовые ограничения.

### Эталон

Твой эталон — работа твоего направления в `stage-0/REFERENCES.md`, «Эталоны направлений», с кадрами в `stage-0/lab/frames/` и калибровкой в `stage-0/CALIBRATION.md`. Он задаёт уровень по «Правилам для всех этапов», раздел «Уровень». Остальные образцы этапа 0 и референсы Ивана — контекст. Новое исследование референсов не проводи.

# Цель

Разработай **один сильный арт-дирекшн** — самостоятельную дизайнерскую систему со своей визуальной логикой. Два других направления делают другие авторы по другим эталонам: не делай безопасный средний вариант.

Направление должно:

- соответствовать продукту и его аудитории;
- выражать позиционирование;
- помогать объяснять продукт;
- быть оригинальным и узнаваемым;
- иметь собственный визуальный характер;
- масштабироваться на весь лендинг;
- быть реалистичным для последующей реализации;
- выглядеть как работа сильной brand/product design team.

Главная задача — найти сильное визуальное решение, а не быстро прийти к безопасному.

# Что определить

Самостоятельно разработай:

- центральную visual idea;
- композиционный принцип;
- grid;
- типографическую систему;
- масштаб заголовков;
- ритм;
- whitespace;
- цветовую систему;
- работу с контрастом;
- фоновые поверхности;
- способ демонстрации продукта;
- стиль product UI;
- изображения, фотографию, иллюстрацию или 3D, если они нужны;
- карточки и контейнеры, если они нужны;
- radii или осознанный отказ от них;
- borders;
- shadows;
- иконографику;
- фирменные графические приёмы;
- характер микроанимаций;
- scroll behaviour;
- фишку в кульминации;
- переходы между состояниями;
- принципы storytelling.

Не пытайся использовать все визуальные инструменты одновременно.

Направление строится вокруг нескольких сильных принципов.

# Не начинай с шаблонов категории

Не считай привычные визуальные стандарты отрасли обязательными.

Сначала пойми продукт и только после этого решай, каким должен быть его визуальный язык.

Избегай шаблонных решений из «Правил для всех этапов» и решений, которые можно практически без изменений перенести на сайт другой компании.

Используй распространённый паттерн только тогда, когда он действительно является лучшим решением задачи.

# Ключевые разделы

Показывай направление не на всей странице, а на ключевых разделах из списка «Ключевые разделы этапа 2» в разделе «Этап 1» `stage-notes.md` — он один для трёх авторов, чтобы сравнивались стили, а не содержание. Тексты, CTA, Visual Intent и общий продуктовый пример этих разделов сохраняются; композиция и визуальная форма могут меняться радикально. Всю страницу в выбранном направлении строит этап 3.

# Фишка в кульминации

Придумай свою фишку — интерактивный приём, которым кульминация этапа 1 показана при прокрутке, — и сделай её работающей в разделе кульминации. Если во входах есть идея фишки, развивай её по-своему. Фишка — самое сильное проявление signature element направления.

Способ — тот, что сильнее для этой фишки:
- код: фигуры, линии, текст и элементы интерфейса меняются вместе с прокруткой;
- слоёные картинки: слои от агента с промптом `../landing-image-generator/generate-landing-image.md`, движение — кодом;
- видео под прокруткой: ролик от агента с промптом `../landing-video-generator/generate-landing-video.md`.

**Сцена — у направления 3, если у продукта есть физический мир или его пользователи в кадре.** Тогда кульминация показана видео под прокруткой или фотосценой слоями: фотография, предметная или 3D-сцена по «Типам визуала» из «Правил для всех этапов». Смысл кульминации передаёт движение самой сцены — камеры, предметов, людей, света. Если у продукта есть интерфейс, интерфейс в работе остаётся в кульминации по разделу «Интерфейс продукта» тех же правил, а сцена его дополняет. Текст — HTML в неподвижном месте поверх сцены. В остальных случаях способ выбирается свободно.

Движение — по «Правилам для всех этапов», раздел «Движение при прокрутке». Если у продукта есть интерфейс, движение раздела главной демонстрации реализуй. Для остальных ключевых разделов достаточно записать приём прокрутки в Execution их зон.

Проверь концепцию съёмщиком scroll-craft (команды и порт твоего направления — в README пайплайна, раздел «Проверка прокруткой») на 1440 px и с выключенной анимацией и посмотри листы кадров кульминации: фишка действительно меняет экран при прокрутке, а без анимации кульминация остаётся понятной.

# Visual intent и пояснения к задумке

Visual intent уже является частью существующего прототипа.

Используй его как один из главных входных параметров дизайна и **не удаляй пояснения после того, как визуальная идея получила конкретную форму**.

Для каждой значимой визуальной зоны проверь:

1. что пользователь должен понять;
2. что он должен почувствовать;
3. какой визуальный сценарий лучше всего передаёт эту идею;
4. почему выбранный визуальный приём подходит именно этой секции.

Визуальная идея должна вытекать из смысла секции.

Сохраняй аннотации по «Правилам для всех этапов» и уточняй в Execution, как задумка реализована в этом направлении. Направление показывает общий продуктовый пример этапа 1.
