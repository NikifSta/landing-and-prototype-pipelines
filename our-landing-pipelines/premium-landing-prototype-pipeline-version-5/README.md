# Premium Landing Prototype Pipeline — версия 5

Поиск образцов уровня и четыре этапа от текста лендинга до страницы с движением при прокрутке, слоистыми визуалами и роликами на десктопе и телефоне. Работает для любого продукта.

## Входы запуска

- текст лендинга, разделённый на смысловые блоки;
- продукт, аудитория и подтверждённые факты о продукте;
- референсы Ивана — либо «нет»; образцы уровня находит этап 0;
- айдентика и ограничения бренда — либо «нет»;
- готовый дизайн приложения. Если у продукта есть приложение, это обязательный вход: ведущий ищет в `dev/pipeline-workspace/` утверждённый прогон пайплайна приложений этого продукта (выбранный дизайн или экраны финальной остановки) и берёт его экраны. Такого прогона нет — лендинг не запускается: ведущий сообщает Ивану, что сначала нужен дизайн приложения. «Нет» пишется только для продукта без приложения;
- другие материалы продукта: фото, видео, логотип — либо «нет»;
- идея фишки — своего интерактивного приёма страницы — либо «нет».

## Этапы

Каждый этап получает свой промпт, [правила для всех этапов](landing-pipeline-rules-for-all-stages.md), входы запуска и результаты предыдущих этапов. Проверяющих нет: автор проходит самопроверку своего промпта и исправляет найденное.

0. [00-find-top-landing-references-and-calibrate-level.md](00-find-top-landing-references-and-calibrate-level.md) — пять лендингов того же рода, признанных за дизайн: кадры, калибровка уровня, три эталона направлений этапа 2 и страница обзора. Остановки нет: после выкладки сразу идёт этап 1.
1. [01-design-landing-prototype.md](01-design-landing-prototype.md) — прототип всей страницы в нейтральном оформлении: рассказ, секции, задания на визуалы, общий продуктовый пример, чувства по секциям и кульминация.
2. [02-explore-three-art-directions-with-signature-moves.md](02-explore-three-art-directions-with-signature-moves.md) — три разных визуальных направления на одних и тех же ключевых разделах, у каждого своя работающая фишка в кульминации. Три автора работают одновременно, по одной сессии на направление: ведущий даёт каждому номер направления 1, 2 или 3, а эталон направления берётся из `stage-0/REFERENCES.md`. После выбора Ивана ведущий переносит `direction-notes.md` выбранного направления в раздел «Этап 2» `stage-notes.md`.
   **Остановка: человек выбирает одно направление** по трём направлениям на странице запуска. Это единственное решение человека внутри процесса.
3. [03-build-page-around-anchor-visuals-with-scroll-motion.md](03-build-page-around-anchor-visuals-with-scroll-motion.md) — три опорных визуала слоями, затем вокруг них вся страница: десктоп и телефон, движение при прокрутке, фишка целиком.
4. [04-produce-remaining-visuals-and-verify-scroll.md](04-produce-remaining-visuals-and-verify-scroll.md) — остальные визуалы слоями, встраивание в движение, проверки на пяти ширинах экрана и прокруткой.

Визуалы этапы заказывают двум пайплайнам: [landing-image-generator](../landing-image-generator/README.md) — изображения слоями, [landing-video-generator](../landing-video-generator/README.md) — ролики под прокрутку.

## Папка запуска

`dev/pipeline-workspace/<ГГГГ-ММ-ДД>-<продукт>-landing/` (вне Git): `inputs/`, `stage-0/` … `stage-4/` и `stage-notes.md` — заметки всех этапов, по разделу на этап. Этапы 2–4 копируют в свою папку движок scroll-craft; на этапе 2 у каждого направления своя папка `stage-2/art-direction-<номер>-<название>/` с движком и заметками `direction-notes.md`.

Образцы этапа 0 — `stage-0/`: `REFERENCES.md`, `CALIBRATION.md`, страница обзора `top-references-overview.html` с картинками в `overview-images/`; сырые кадры — `stage-0/lab/frames/`.

Папка визуалов — `visuals/` в папке этапа: опорные визуалы этапа 3 — в `stage-3/visuals/`; этап 4 копирует страницу и визуалы этапа 3 в `stage-4/` и добавляет остальные в `stage-4/visuals/`.

## Показ на странице запуска

После каждого этапа тот, кто ведёт запуск, выкладывает готовые этапы на страницу запуска и отправляет Ивану в подтверждённый личный Telegram одно сообщение: ссылку на страницу запуска и прямую ссылку этапа. Из корня проекта:

```bash
.venv/bin/python dev/pipelines/premium-landing-prototype-pipeline-version-5/tools/landing_run_page_publisher.py \
  --run-folder <папка запуска> --product-name "<название продукта>" --stage <номер этапа>
```

Выкладываются этапы с 0-го по указанный: папки `stage-N/` без `lab/`, `node_modules/`, заметок `*.md` и скрытых файлов, с оглавлением по этапам; ссылки оглавления открывают страницы в чистом просмотре без аннотаций. Страница запуска — одна постоянная ссылка `https://my.holdi.ai/prototypes/<продукт>-landing-<код>/`, открывается без входа; адрес хранится в `published-run-page-address.txt` папки запуска. Если Telegram в сессии недоступен — ссылка даётся в ответе сессии с пометкой, что в Telegram она не ушла. Если выкладка не удалась — причина сообщается Ивану; файлы или показ в чате её не заменяют.

## Проверка прокруткой

Съёмщик скилла scroll-craft проходит страницу по точкам прокрутки, снимает кадры и лист кадров `sheet.png`, пишет `report.json` с мёртвой прокруткой, недопроявленными подсказками и контрастом. Один раз в папке запуска: `npm i playwright-core`. Три автора этапа 2 работают одновременно, поэтому направление N поднимает сервер на порту 4500 + N, а папка этапа для него — папка направления; остальные этапы — порт 4500. Затем из папки запуска:

```bash
SC=/home/ivan/claude-sandbox/hypothesis-tester/.claude/skills/scroll-craft
node "$SC/scripts/serve.mjs" --root <папка этапа> --port <порт> &
node "$SC/scripts/shoot.mjs" --url http://localhost:<порт>/<страница>.html --out <папка этапа>/lab/desktop
node "$SC/scripts/shoot.mjs" --url http://localhost:<порт>/<страница>.html --out <папка этапа>/lab/phone --width 390 --height 844
node "$SC/scripts/shoot.mjs" --url http://localhost:<порт>/<страница>.html --out <папка этапа>/lab/reduced --reduced-motion
```

Прочитай `sheet.png` каждого прогона: съёмщик доказывает, что кадры меняются, но не что композиция хороша. Реальный телефон он не проверяет.
