# Этап 2. Уровень, формат результата и самопроверка

Вторая часть промпта этапа 2; первая — `02-explore-three-art-directions-with-signature-moves.md`. Читай обе до начала работы.

# Product storytelling

Показывай продукт через действие, изменение состояния, причинно-следственную связь, процесс и результат, а не только через статичный скриншот интерфейса.

В зависимости от продукта естественный сценарий может выглядеть, например:

проблема → действие → работа продукта → результат;

ввод → обработка → результат;

до → во время → после;

объект → трансформация → новый объект;

данные → анализ → решение;

событие → реакция системы → эффект.

Это не готовые шаблоны.

Найди естественную историю именно конкретного продукта.

Визуальное представление должно помогать понять продукт ещё до подробного чтения текста.

# Уровень исполнения

Каждый крупный визуальный элемент должен выполнять хотя бы одну функцию:

- объяснять продукт;
- показывать его действие;
- усиливать позиционирование;
- направлять внимание;
- создавать эмоциональный характер;
- поддерживать узнаваемость бренда.

# Где должна появиться «магия»

Не откладывай красоту, характер и выразительность на будущий production-этап.

Уже на стадии арт-дирекшна концепция должна ощущаться как сильный, визуально убедительный сайт и демонстрировать:

- собственный характер бренда;
- выразительную композицию;
- сильную типографику;
- уверенную работу с цветом и пространством;
- signature element;
- работающую фишку в кульминации;
- визуальный storytelling;
- характер движения и переходов;
- продуманный способ демонстрации продукта;
- достаточное количество деталей, чтобы направление можно было честно оценить по красоте и потенциалу.

Не выдавай «функциональный каркас», предполагая, что красота появится позже. Если направление сейчас не вызывает визуального интереса, оно ещё не прошло этап арт-дирекшна.

При этом **финальный production polish выполняется после выбора одного направления**. На следующем этапе могут быть доведены:

- опорные и остальные визуалы;
- точные продуктовые состояния интерфейса; сам интерфейс в ключевых разделах уже взят из готового дизайна приложения, если у продукта есть приложение;
- движение остальных разделов;
- микротипографика и оптическая доводка;
- финальные shadows, textures, transitions и micro-interactions;
- телефонная версия;

То есть арт-дирекшин должен уже содержать **главную красоту и визуальную магию**, а следующий этап — не изобретать её заново, а довести выбранную систему до финального качества.

# Signature element

Найди минимум один потенциальный **signature element** — визуальный принцип, способ подачи или поведения, который может стать характерным именно для этого бренда.

Это может быть:

- типографический принцип;
- характер движения;
- необычная работа с интерфейсом;
- пространственная система;
- графический объект;
- особая работа с изображениями;
- форма;
- трансформация;
- визуальная метафора;
- уникальный ритм;
- способ перехода между состояниями.

Цель — чтобы фрагмент сайта потенциально можно было узнать даже без логотипа.

# Формат результата

Создай **одну работающую концепцию в HTML/CSS/JS** в папке `stage-2/art-direction-<номер>-<короткое-название>/`: страница, движок scroll-craft, визуалы, `lab/`.

Концепция должна:

- содержать все ключевые разделы;
- сохранять тексты, смыслы и CTA ключевых разделов;
- сохранять рабочие пояснения Visual Intent / Role / Execution для значимых визуальных зон;
- показывать работающую фишку в кульминации при прокрутке;
- открываться как настоящий сайт в браузере;
- использовать гибкую responsive-вёрстку;
- хорошо работать на desktop и корректно адаптироваться под mobile;
- последовательно применять арт-дирекшн ко всем ключевым разделам.

Основной акцент этого этапа — качество desktop-арт-дирекшна. Mobile должен быть корректным и usable, но его полноценная hi-fi доводка будет сделана на этапе 3.

Не отдавай концепции только в виде изображений, moodboard, Figma-like canvas или презентационных слайдов.

Помимо концепции запиши краткую спецификацию в `direction-notes.md` в папке направления — не в `stage-notes.md`: три автора работают одновременно. Она **дополняет**, а не заменяет пояснения внутри прототипа.

# Краткая спецификация направления

Укажи:

**Эталон**  
REF-ID эталона направления; ответы сверки уровня и что убрано на последнем шаге, с причиной.

**Название направления**  
Короткое рабочее название.

**Central idea**  
Одно предложение с главной дизайнерской идеей.

**Visual logic**  
Краткое описание принципа композиции и визуального языка.

**Signature element**  
Главный потенциально узнаваемый приём.

**Product storytelling**  
Как направление показывает работу продукта.

**Motion character**  
Как должен вести себя сайт в движении.

**Фишка**  
Что происходит в кульминации при прокрутке и чем это сделано: код, слоёные картинки или видео.

**System rules**  
Ключевые правила, по которым этот визуальный язык уже применён ко всем ключевым разделам и должен сохраняться, когда этап 3 строит всю страницу.

# Самопроверка

Перед финальной выдачей критически проверь направление по критериям:

1. визуальное качество;
2. соответствие продукту;
3. оригинальность;
4. узнаваемость;
5. понятность продукта;
6. качество product storytelling;
7. целостность системы;
8. масштабируемость на весь лендинг;
9. реалистичность реализации.
10. фишка работает при прокрутке, а без анимации кульминация остаётся понятной; у направления 3 — сцена, если условие сцены из первой части промпта выполняется.

**Уровень рядом с эталоном.** Поставь верх каждого ключевого раздела на 1440 px рядом с кадром эталона в одном масштабе и ответь: так же ясно показан продукт? так же заметно меняется кадр при прокрутке — по калибровке? нет ли рядом с эталоном чего-то странного: брака, лишнего, случайного?

Если направление является:

- типовым шаблоном;
- набором модных эффектов;
- красивой, но бессмысленной композицией;
- дизайном, слабо связанным с продуктом,

переработай его до финальной выдачи.

**Последний шаг — убрать.** Снова рядом с эталоном в одном масштабе убери рамки, плашки, цвета и элементы, без которых раздел сильнее. Убранное с причиной и ответы сверки — в `direction-notes.md`.

# Финальное ограничение

Сделай одно направление: без запасных и компромиссных вариантов.
