# Экраны продукта

Интерфейсы продукта — всегда HTML/CSS кодом, не картинкой. Результат этапа — `projects/<slug>/08-ui/`: общие `ui.css` и `ui.js`, по одному фрагменту на секцию сценария с интерфейсом, `README.md`, скриншоты `shots/`.

## Пути
- **Корень плагина** — два уровня выше этого файла (`skills/ui/` → `../../`): `templates/ui/ui.js`, `scripts/`, `CLAUDE.md`. Команды `node scripts/…` в этом скилле означают `node "<корень плагина>/scripts/…"`; запускай их **из рабочей папки пользователя** (там лежат `projects/` и по желанию `.env`; скрипты сами читают `.env` рабочей папки и корня плагина). `references/`, `templates/`, `schemas/` лежат в корне плагина, пути `projects/<slug>/…` — в рабочей папке. Не переходи в корень плагина и не создавай проекты внутри него.
- **Проект** — `projects/<slug>/` в текущей рабочей папке; slug — имя папки, аргумент `$ARGUMENTS` (не передан — первый проект, где отмечен art-direction, но не ui).
- Нет `06-art-direction.md` с отметкой «Выбрано» — сначала art-direction.

## Шаги

### 1. Вход
Прочитай `06-art-direction.md` (общие правила карточек и карточка каждой секции), `05-brand.json` (токены), `04-demo-story.md` (все данные), `03-story.md` (тексты секций), `open-questions.md`. Список фрагментов — по карточкам: каждая секция с интерфейсом или сценой получает файл `NN-имя.html`; блоки без сцены (чистый текст) в `08-ui/` не нужны.
Каждый фрагмент реализует **композицию своего архетипа** из `recipe.json` и карточки арт-дирекции (ASCII-схема, поле, главный объект, движение), а не общий «заголовок + плитка с окном». Блоки одной страницы должны отличаться видом: не делай два блока по схеме «список шагов слева + окно справа», «ряд одинаковых карточек» или «таблицы-вкладки», если рецепт этого не требует; общие компоненты (`ui.css`) — только словарь (кнопки, строки, аватары, статус-плашки), а не каркас блоков.
Тяжёлую вёрстку выполняй **субагентом с чистым контекстом** (если ты уже запущен как субагент этого этапа, делай сам) (передай: пути к `06-art-direction.md`, `recipe.json`, `04-demo-story.md`, `05-brand.json`, `07-media/final/` и правила ниже); основная сессия получает короткий итог и скриншоты.

### 2. Общие файлы
- `ui.css`: токены из `05-brand.json` как CSS-переменные (цвета со смыслом, `…OnDark`, радиусы, тени, шрифты), компоненты (плитка, кнопка, строка, аватар, статус-плашка, поле), правила сцены. Состояния сцены лежат **в одной ячейке** (`.stack{display:grid}`, дети `grid-area:1/1`, скрываются прозрачностью, а не `display:none`).
- `ui.js`: скопируй `templates/ui/ui.js` без правок (запуск сцены при появлении, цикл с паузой, конечное состояние при `prefers-reduced-motion`, подсчёт числа `countTo`/`rollTo`, `setState`). Свою логику сцен пиши в самом фрагменте. Для телефона скопируй каркас из `templates/ui/phone.css` в `ui.css`.
- Зарезервированные имена `ui.css`: `.tile`, `.cap`, `.btn`, `.line`, `.av`, `.pill`, `.num`, `.stack`, `.off`, `.split`, `.side`, `.big`, `.phone`, `.scr`. Свои классы называй по смыслу фрагмента (`.gcard`, `.badge`, `.mo`), чтобы не столкнуться с общими.
- Шрифты бренда подключи ссылкой Google Fonts с `subset=cyrillic`; числа — табличные цифры.

### 3. Фрагменты
Каждый фрагмент — отдельный HTML (`lang="ru"`, `meta viewport`, `<title>`), подключает `ui.css`, `ui.js` и шрифты; данные только из `04-demo-story.md` (производные числа допиши туда формулой). Правила:
- **Размеры.** Высота плитки и секции не меняется ни в одном состоянии анимации: место под итоговые значения занято с начала, меняющийся текст получает высоту под самый длинный вариант. Класс появления не вешай на элемент со своим `transform` (масштаб устройства): анимируй обёртку. Классы анимации не меняют `display` контейнера.
- **Начальное состояние не пустое:** заглушки «— ₽», «считаю…», серые строки.
- **Автосцены:** запускаются при появлении (`loopScene`), крутятся по кругу с паузой в конце, без кнопки «повторить»; прокрутка управляет только простым (прогресс, смена шага). Для `prefers-reduced-motion` — конечное состояние.
- **Устройства — опция, а не обязательный блок.** Мокап телефона делай, только если карточка арт-дирекции его требует (приложение или сценарий с телефона сказан в сценарии). Платформа по умолчанию iOS; содержимое экрана строй по `references/platform-guidelines.md` (статус-бар, большой заголовок/навбар, сгруппированные списки, tab bar, безопасные зоны, размеры шрифтов и зон нажатия), а не как «мини-сайт».
- **Устройства** — рамки кодом по гайдлайнам платформы: телефон — экран 390×844, скругление, динамический остров или вырез, статус-бар (время, связь), индикатор «домой», безопасные зоны; внутри та же вёрстка интерфейса, уменьшенная целиком (`transform: scale`), без отдельной «мини-версии». Блок про мобильное приложение — 2–3 экрана с разными сценариями.
- **Заполнение.** Экран не должен иметь больших пустых зон: достаточно строк, карточек, состава заказа; но без повторяющихся элементов, которые ничего не показывают.
- **Тексты:** заголовки `text-wrap: balance`, абзацы `pretty`, у `h1`–`h3` `font-variant-numeric: proportional-nums` (табличные цифры только для сумм и счётчиков); кнопки имеют отступы, текст кнопки — один узел; суммы с `white-space: nowrap`.
- **Тестовые значения и «[уточнить: …]»:** если фрагмент содержит значения из `open-questions.md`, помечай `data-test-values="open-questions-N"` и комментарием в коде; нет таких значений — ничего не добавляй.
- **При расхождении** карточки арт-дирекции и `03-story.md` главнее арт-дирекция (расхождения записаны в «Отклонениях от сценария»).
- **Счётчики:** начальное состояние — «0 ₽» допустимо, если число считается один раз при появлении, для сцены с заглушками — «— ₽». В `prefers-reduced-motion` показывается итог сцены (конечное состояние); сводка месяцев по желанию.
- **Шрифты Google недоступны** (нет сети) — страница работает на запасном шрифте стека; не блокируй этап, но отметь это в итоге.
- **Адаптив:** на 390 px колонки встают друг под другом (у разреза «слева тёмная, ниже светлая»), горизонтальной прокрутки нет.
- **Доступность:** видимый фокус у полей и кнопок, достаточный контраст (`scripts/contrast.mjs` для сомнительных пар).

### 4. Проверка
Для каждого фрагмента:
1. Типограф запускай **последним**, когда правки текста закончены: `node scripts/typograph.mjs projects/<slug>/08-ui/NN-имя.html` склеивает короткие слова неразрывными пробелами, и после него поиск-замена по строкам молча не находит текст. Нужно поправить после типографа — меняй по уникальному фрагменту без пробелов или сначала замени NBSP на обычные пробелы. Тексты, которые подставляет JS, склей вручную неразрывным пробелом.
2. `node scripts/shots.mjs projects/<slug>/08-ui/NN-имя.html projects/<slug>/08-ui/shots NN-имя`. Условие: `scrollWidth` 1440 и 390. Есть прокрутка — `node scripts/overflow.mjs <файл> 390` назовёт элементы, которые вылезают (отладочные скрипты в корень плагина не клади). Посмотри картинки (`Read` на png): читаемость, правдоподобие, единый стиль, пустые зоны (на экране устройства — не более ~15 % высоты экрана), обрезанные плашки, висячие слова, перекрытия, кегль в масштабированном экране (после `scale` подписи не меньше ≈ 9 px).
3. **Автосцены** `shots.mjs` не показывает (снимает одну фазу): запусти `node scripts/time-shots.mjs <url файла> projects/<slug>/08-ui/shots/t-NN <мс через запятую>` (опция `--y=<px>` прокручивает к сцене, если она ниже первого экрана) и посмотри кадры: начальное состояние (≈ 900 мс), середина, итог, пауза и начало следующего цикла. Высота плитки на всех кадрах одинакова.
4. Недочёты исправь и пересними. Затем сверь числа и имена с `04-demo-story.md` (поиском по файлам), в том числе даты и дни недели.

## Контракт фрагмента и сборки (из практики прогонов)
- Фрагмент — **содержимое одной секции**: без `<header>`, `<nav>`, `<main>`, `<footer>` и якорей меню: их даёт `site/src/page.html`. Скрипт сборки предупредит, если нарушено.
- Названия классов фрагмента — по смыслу блока и **не совпадают** с общими именами `ui.css` и другими фрагментами (`.card`, `.chip`, `.price`, `.hd` — запрещены как короткие общие). Стили фрагмента изолируются при сборке (`@scope`), но общие имена из `ui.css` всё равно перебьют их.
- `@keyframes` в стилях фрагмента при сборке выносятся на верхний уровень (внутри `@scope` они ненадёжны); называй их уникально (`f3-fly`, не `fade`). `:root` и `body` в стилях фрагмента не используй: токены лежат в `ui.css`.
- **Обвязка предпросмотра** (отступы `height:40vh` вокруг сцены, чтобы посмотреть закрепление) не клади в разметку `<body>`: в сборку попадает всё содержимое body, и между секциями появятся провалы. Задавай её стилем `body` в самом фрагменте или временным файлом. Сборка предупредит об элементах с высотой в `vh`.
- **Заголовок секции**: по умолчанию его даёт `page.html` над сценой, но если архетип требует иного (collage — предметы вокруг заголовка, hero — H1 часть композиции, split-field — заголовок слева, окно справа), заголовок кладётся во фрагмент, а в `page.html` для такой секции оставляется только якорь. Запиши это в `08-ui/README.md`.
- **Закреплённая сцена (pin)**: GSAP-пин внутри `@scope`-фрагмента с переименованием id рискован. Делай `position: sticky` в контейнере высотой N экранов и смену шага по прокрутке (`scroll`-слушатель с `requestAnimationFrame` или `IntersectionObserver` по шагам). Подключать ScrollTrigger для такого случая необязательно: правило CLAUDE.md про GSAP относится к `scrub`/`parallax`. Все состояния лежат в одной ячейке, высота сцены постоянна.
- **Тестовые значения на странице не помечаются**: никаких «тестовая цена» и «пример» в тексте и плашках, значения выглядят как настоящие; пометка только невидимым `data-test-values` и в `open-questions.md`; о них сообщается пользователю в чате.
- **Вырезки предметов «на однотонном фоне»** (рулетка, калькулятор) цветом не совпадают с полем: сведи края CSS-маской (`mask-image` с градиентом) или ставь предмет на плашку/тень, а не обещай «сливается с фоном».
- Ленты и карусели с `scroll-snap` внутри `grid`/`flex` требуют `min-width:0` у колонки, иначе на 390 появляется горизонтальная прокрутка.
- **Грамматика контейнера** берётся из рецепта (`recipe.json → sections[].container`) и карточки арт-дирекции: `framed-window` (окно интерфейса в рамке), `full-bleed` (график, фото, поле на всю ширину), `typographic` (только типографика), `object-on-field` (предмет, иллюстрация, 3D), `ribbon` (лента, бегущая строка, линия времени), `grid-cards`, `split-field`. **Нельзя** по умолчанию класть каждый блок как «белая карточка с интерфейсом на цветной плитке»: так сходятся к одной схеме все страницы. После вёрстки проверь страницу `node scripts/block-variety.mjs <site/index.html>` (после сборки).
- Снимки из `07-media/final/`: копируй в `site/assets/` и подключай так: `<img src="../site/assets/x.jpg" data-site-src="assets/x.jpg">` (путь для фрагмента и путь для сайта). Положение пустых областей на снимке (для наложения кодом) возьми из `07-media/README.md`.
- Не повторяй один и тот же материал (один отчёт, один экран) в трёх блоках: у каждого блока свой повод и свои данные.

## Ядро доказательства: рабочий инструмент
Если в `03-story.json` есть `proof_core` (не `none`), фрагмент ядра (и первый экран при `placement: hero`) делается как **рабочий интерфейс**: настоящие `<input type="range|number|text">`, `<select>`, кнопки; пересчёт на каждом `input`; правдоподобные значения по умолчанию; результат крупно и мгновенно. Введённые значения пишутся в `PageState` (`templates/ui/ui.js`) и подхватываются блоками `reused_in` (сравнение, итоги, форма). Состояния лежат в одной ячейке, высота блока постоянна; поля подписаны (`label`), с видимым фокусом; на 390 px инструмент перестраивается (поля над результатом), а не уменьшается. Автосцена — только как подсказка при появлении (один проход), потом управление у посетителя. Проверка: `node scripts/interactivity-check.mjs <страница>` (должно найти управляемые поля и изменение результата).
