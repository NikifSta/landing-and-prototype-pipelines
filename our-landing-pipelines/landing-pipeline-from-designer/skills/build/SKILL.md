# Сборка лендинга

Результат этапа — `projects/<slug>/site/index.html` (один файл: стили и скрипты внутри, внешне только шрифты Google) и `site/assets/` (логотип, знак, при необходимости изображения). Страница собирается **скриптом из шаблона и фрагментов**, чтобы её можно было пересобирать после любой правки экранов.

## Пути
- **Корень плагина** — два уровня выше этого файла (`skills/build/` → `../../`): `scripts/build-site.mjs`, `scripts/typograph.mjs`, `scripts/shots.mjs`, `scripts/section-shots.mjs`, `scripts/qa.mjs`, `CLAUDE.md`. Команды `node scripts/…` в этом скилле означают `node "<корень плагина>/scripts/…"`; запускай их **из рабочей папки пользователя** (там лежат `projects/` и по желанию `.env`; скрипты сами читают `.env` рабочей папки и корня плагина). `references/`, `templates/`, `schemas/` лежат в корне плагина, пути `projects/<slug>/…` — в рабочей папке. Не переходи в корень плагина и не создавай проекты внутри него.
- **Проект** — `projects/<slug>/` в текущей рабочей папке; slug — имя папки, аргумент `$ARGUMENTS` (не передан — первый проект, где отмечен ui, но не build).
- Нет `08-ui/` — сначала ui. Нужны изображения по карточкам арт-дирекции, а `07-media/` нет — сначала media.

## Перед началом: открытые вопросы
Прочитай `open-questions.md`. Открытые вопросы без ответа — стоп: покажи их пользователю и дождись ответа или разрешения использовать тестовые значения (тогда `build`, `qa` и `publish` идут с ними, значения не помечаются на странице: о них сообщается в чате). Тестовые значения не прячь: в коде они остаются с пометкой `data-test-values`.

## Шаги

### 1. Шаблон страницы `site/src/page.html`
Один HTML с плейсхолдерами `{{ui.css}}`, `{{ui.js}}`, `{{fragment:NN-имя}}`, `{{fragment-styles}}`, `{{fragment-scripts}}`. Содержит:
- `<head>`: `lang="ru"`, `<title>` и `description` по сценарию, Open Graph, `theme-color`, favicon из `assets/mark.svg`, подключение шрифтов бренда (`subset=cyrillic`);
- шапка (логотип — SVG знака в разметке + надпись шрифтом бренда; логотип и пункты меню на одной базовой линии), ссылка «К содержанию», `<main>`, подвал;
- секции строго по `03-story.md` и карточкам `06-art-direction.md`: заголовок и пояснение **над** сценой (готовый текст из сценария), ниже плейсхолдер фрагмента; исключение — секции, где по архетипу заголовок часть композиции (collage, hero, split-field): их заголовок лежит во фрагменте (см. контракт в `skills/ui`), в `page.html` остаётся только якорь и плейсхолдер; ритм фонов и отступы секций — по системе арт-дирекции (секции 104/72 px и т. д.);
- первый экран: заголовок объясняет пользу, подзаголовок ≤ 2 строк на 1440, кнопки с отступом;
- ссылки навигации ведут на якоря секций; призыв к действию один (форма в конце).
- CSS страницы: `.frag{padding:0;max-width:none}` (внутри секции), `html{scroll-behavior:smooth}` с отключением при `prefers-reduced-motion`, видимый фокус, адаптив на 390 px (колонки друг под другом, поля 16 px).
- Анимации: автосцены уже в фрагментах (`loopScene`); GSAP ScrollTrigger подключай только если карточка требует `pin`/`scrub`/`parallax`. Параллакс полноэкранных фото запрещён. Класс появления не вешай на элемент со своим `transform` или с `display: flex/grid`.

### 2. Сборка
`node scripts/build-site.mjs projects/<slug>`. Скрипт вставляет разметку фрагментов, изолирует каждый: `id` с префиксом `fNN-`, стили в `@scope (#fNN)`, скрипты в блоке `{ }`. Затем `node scripts/typograph.mjs projects/<slug>/site/index.html` (после каждой пересборки: сборка стирает неразрывные пробелы; правки текста делай до типографа). Файлы логотипа и знака скопируй в `site/assets/`.
Правки вносятся в `page.html` и фрагменты `08-ui/`, потом сборка повторяется; `site/index.html` руками не редактируется.

### 3. Проверка
1. `node scripts/qa.mjs projects/<slug>/site/index.html projects/<slug>/qa` — скриншоты 1440 и 390, горизонтальная прокрутка, наложения, висячие слова, высота блоков 10 с на каждом, ошибки JS. Работает минуты: запускай в фоне. В ходе работы скрипт пишет прогресс в stderr; итоговый отчёт печатается в конце. Намеренные слои (`aria-hidden`, `.stack`, пары с одинаковым текстом) в наложения не попадают; допустимое срабатывание — `a.skip` (скрытая ссылка «К содержанию»). Остальные наложения проверяй глазами по скриншотам: список показывает уникальные пары.
2. Просмотр глазами: `node scripts/section-shots.mjs projects/<slug>/site/index.html projects/<slug>/site/shots <id,id,…> --wait=9500` для секций с автосценами (кульминация), `--width=390` для телефона. Посмотри картинки (`Read` на png).
3. Исправь найденное в `page.html` или фрагментах, пересобери, повтори до нуля по пунктам: горизонтальная прокрутка, блоки меняют высоту, висячие слова, ошибки JS. Одно слово на последней строке у заголовков на телефоне уменьшай размером кегля.
4. Ключевые числа и тексты на странице сверь с `04-demo-story.md` и `03-story.md`.

### 4. Чеклист и итог
Отметь в `checklist.md`: `- [x] 9. build — \`site/index.html\` — <дата>`. Если есть тестовые значения — допиши «(тестовые значения: open-questions № N)».

- Все числа и имена совпадают с демо-историей; тестовые значения помечены.

## Из практики прогонов
- **Граница фрагментов:** шапка, подвал, `<main>` и навигация — только в `page.html`; фрагменты их не содержат (скрипт предупреждает). Ссылки-якоря меню перенаправляются на переименованные id автоматически; несуществующие якоря скрипт перечисляет в предупреждении.
- **Проверка разнообразия:** после сборки `node scripts/block-variety.mjs projects/<slug>/site/index.html`. Проблемы («много карточек на фоне», «нет ритма фонов», три одинаковые секции подряд) исправляй вёрсткой фрагментов, а не оправданиями.
- **Безопасная зона в карточках:** `node scripts/edge-check.mjs projects/<slug>/site/index.html` (1440 и 390) — текст и значки не ближе 16 px (на телефоне 12 px) к краю карточки, плашки, окна, билета; нарушений 0. Слои в масштабе и под углом меряются в собственных координатах; исключение только `data-edge-ok` с причиной (таб-бар iOS).
- **Отступления от арт-дирекции** (цвет подвала, форма вместо кнопки и т. п.) допустимы по просьбе пользователя или по смыслу, но их записывай в `06-art-direction.md` (раздел «Отклонения») и в `recipe.json` (`refresh`), чтобы документы не расходились со страницей.
- Не клади отладочные файлы в `scripts/` плагина: для замеров используй `node scripts/probe.mjs <страница> "<выражение>"`.
- Если ты запущен как субагент этого этапа, работай сам, без вложенных субагентов.
