# Поиск и добавление референсов

Страница должна быть похожа на **выбранный пользователем референс** по стилистике. Если в каталоге мало его блоков или нет блока нужной роли, не подмешивай случайные чужие: найди **похожие** сайты, разбери их и добавь в базу. Так база растёт, выбор становится шире, страницы повторяются реже.

## Пути
- Корень плагина — два уровня выше этого файла. Команды `node scripts/…` — из корня плагина (в режиме «одна папка» это рабочая папка). Ключи и `.env` не читай и не печатай.
- Всё добавляемое лежит в `references/`: паспорт `references/<ref-id>.md`, превью `thumbs/` и `blocks/`, архетипы `references/_archetypes/part-added-<ref-id>.json` и `…languages.json`. Формат архетипов — `references/_archetypes/_SCHEMA.md` (прочитай целиком).

## Шаги

### 0. Сначала углубить сам выбранный референс
Доля собственных блоков выбранного референса низкая, потому что в каталоге мы записали только 6–13 его блоков, а на странице их обычно больше. Прежде чем искать чужие сайты:
1. Сравни роли страницы (`03-story.json`) с архетипами референса (`recipe.json → primary`; `references/_archetypes/part-*.json`, donors.ref = primary): каких ролей у него нет (hero, mechanism, data-viz, comparison, devices, pricing, cta, footer…).
2. Для каждой недостающей роли открой полосы `references/blocks/<primary>/NN.jpg` и `references/shots/<primary>/code/summary.md`: есть ли на его странице блок такой роли? Если есть, опиши его архетип (формат `_SCHEMA.md`, donors.ref = primary) в `references/_archetypes/part-added-<primary>-deep.json`. Не выдумывай блоки, которых не видел.
3. Пересоздай кандидатов (`recipe.mjs candidates`): доля собственных блоков выбранного референса должна вырасти. Только если её по-прежнему мало, переходи к поиску похожих сайтов.

### 1. Понять, что искать
Прочитай паспорт выбранного референса (`references/<ref>.md`), его язык (`references/_archetypes/part-*.languages.json`) и список ролей страницы (`03-story.json`) или недостающие роли из вывода `recipe.mjs check`. Сформулируй запрос: настроение, палитра, тип продукта (consumer / B2B / fintech…), какие роли блоков нужны (hero, mechanism, data-viz, devices, pricing…).

### 2. Найти кандидатов (3–5 сайтов, не больше `--n`)
Источники по порядку, каждый, который отвечает:
1. **MCP `designmd`** (каталог дизайн-систем: палитра, шрифты, настроение; проверен, отвечает): `search_design_kits` (1–2 слова или теги: `fintech`, `saas`, `landing-page`, `dark`; сортировка `downloads`), `list_popular_kits`, `get_design_kit`. Это идеи для **бренда и палитры** похожего по настроению сайта, а не композиции блоков; в описании иногда указан исходный сайт («extracted from …»): его URL бери как кандидата для шага 3. Нет сервера или он не отвечает: подожди подключения через `ToolSearch`, потом переходи к пункту 2.
2. Запасной каталог: `node scripts/design-kits.mjs list|get`.
3. Поиск в сети (`WebSearch`): «landing pages like <референс>», «best <тип продукта> landing page», галереи лендингов (Lapa Ninja, Land-book, Godly, Awwwards, SaaSLandingPage, Httpster). Бери **живые страницы продуктов**, а не статьи.
Для каждого кандидата открой страницу (браузер или `WebFetch`) и проверь: сильный ли лендинг, похож ли по настроению, есть ли нужные роли блоков. Отсеивай шаблонные страницы и страницы с запрещёнными клише (CLAUDE.md).

### 3. Добавить в базу (по одному сайту)
```
node scripts/add-reference.mjs <https://адрес> <ref-id> --name="Название"
```
Скрипт сам снимет код страницы (`inspect.mjs`), полностраничный скриншот, превью первого экрана и полосы блоков, создаст заготовку паспорта. Сайт не открылся: цепочка из CLAUDE.md (PROXY → архивная копия → WebFetch → «не проверен»); в паспорте пиши, какая версия снята.
Разрешение на скачивание страниц для изучения даёт сам запрос пользователя «найди похожие»; сторонние файлы не исполняй.

### 4. Заполнить паспорт и записать архетипы
1. Открой `references/blocks/<ref-id>/NN.jpg` (Read на каждую полосу, не меньше 5) и `references/shots/<ref-id>/code/summary.md`.
2. Допиши паспорт: настроение, палитра, шрифты, как показан продукт, **есть ли на самом деле** бегущая строка, закрепление, параллакс, видео (по коду и полосам, не по догадке).
3. Запиши архетипы блоков в `references/_archetypes/part-added-<ref-id>.json` (массив, один блок страницы = одна запись, не страница целиком; поля `id`, `role`, `family`, `composition`, `ascii`, `background`, `density`, `motion`, `imagery`, `needs`, `fits`, `donors` с `ref: <ref-id>`, `distinctive`) и язык в `part-added-<ref-id>.languages.json` (одна запись). Описывай идею и композицию, не копируй тексты и формы. Не выдумывай блоки, которых не видел. Минимум 6 архетипов на сайт.
4. Проверь JSON (`node -e "JSON.parse(require('fs').readFileSync('<файл>','utf8'))"`), затем `node scripts/catalog-stats.mjs`: новые архетипы и ссылки `avoid_same_page_as` должны быть валидны.

### 5. Применить
Пересоздай кандидатов или обнови рецепт: `node scripts/recipe.mjs candidates projects/<slug>` (или `swap` для замены блока на новый), затем `recipe.mjs check`: доля блоков выбранного референса и похожих должна вырасти. Запиши в `decisions.md`, какие сайты добавлены и почему.

## Проверка перед завершением
- У каждого добавленного сайта есть паспорт, превью (`thumbs/`, `blocks/`), код (`code/summary.md`) или пометка «не проверен», архетипы и язык; JSON валиден.
- Блоки описаны по увиденному; приёмов (marquee, pin, 3D) в записи нет, если на сайте их нет.
- Ничего не скопировано дословно (тексты, формы, палитры).

## Из практики
- Для релиза превью и паспорта лёгкие (десятки КБ), тяжёлые скриншоты остаются только локально.
- Кандидатов на доске вкуса (`taste-board.mjs auto`) выбирают из языков, у которых есть превью первого экрана: новые сайты автоматически попадают на доску.
